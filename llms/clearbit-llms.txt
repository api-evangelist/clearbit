# Clearbit (HubSpot Breeze Intelligence)

> B2B person and company enrichment. Resolve an email to a person, a domain to a company, or an IP
> address to the business behind it. Acquired by HubSpot in December 2023 and now in publicly dated
> wind-down: the APIs below are live, but new API keys have not been issued since 2023 and the free
> tools and Logo API have been sunset. Only the Autocomplete API is callable without a credential.

This file was GENERATED by API Evangelist from the artifacts in the api-evangelist/clearbit repo.
Clearbit does not publish an llms.txt — probed https://clearbit.com/llms.txt and
https://dashboard.clearbit.com/llms.txt on 2026-08-13, both 404.

## Status (verified 2026-08-13)

- No OpenAPI, Swagger, AsyncAPI or GraphQL SDL is published anywhere on the Clearbit estate.
- The API reference at https://dashboard.clearbit.com/docs is a client-rendered SPA; the served
  HTML is an empty shell.
- New API key issuance is closed. Accounts created after 2023 cannot obtain a credential.
- `logo.clearbit.com` was sunset 2025-12-08 and no longer resolves in DNS.
- Every first-party SDK's last release predates the HubSpot acquisition.

## APIs

- [Enrichment (Person)](https://person.clearbit.com/v2/people/find): GET `?email=` — enriched
  person profile. Auth required. May return 202.
- [Enrichment (Company)](https://company.clearbit.com/v2/companies/find): GET `?domain=` —
  enriched firmographic record. Auth required.
- [Enrichment (Combined)](https://person.clearbit.com/v2/combined/find): GET `?email=` — person
  and company in one response. Auth required.
- [Streaming Enrichment](https://person-stream.clearbit.com/v2/combined/find): same contract, but
  holds the connection open up to 60s so a queued lookup resolves in-band instead of returning 202.
- [Reveal](https://reveal.clearbit.com/v1/companies/find): GET `?ip=` — company behind an IP.
- [Prospector](https://prospector.clearbit.com/v1/people/search): GET `?domain=` — people search.
- [Discovery](https://discovery.clearbit.com/v1/companies/search): GET `?query=` — company search.
- [Name to Domain](https://company.clearbit.com/v1/domains/find): GET `?name=` — company name to
  domain. Legacy, unsupported.
- [Risk](https://risk.clearbit.com/v1/calculate): GET `?email=` — fraud/abuse score. Legacy,
  unsupported.
- [Autocomplete](https://autocomplete.clearbit.com/v1/companies/suggest): GET `?query=` — company
  candidates. FREE, no API key, CORS-enabled. `logo` always returns null.

## Calling it

- Auth: one account secret API key, as HTTP Basic (key as username, empty password) or as
  `Authorization: Bearer <key>`. No OAuth, no scopes.
- Versioning: dated account versions, echoed on every response in `x-api-version`. Your version is
  pinned on first call and never changed without you.
- Errors: `{"error": {"type": "<slug>", "message": "<prose>"}}` as `application/json`. Not RFC 9457.
  Branch on `type`. Known types: `auth_required`, `invalid_api_key`, `unknown_route`.
- **202 is not an error.** It means the lookup is queued. Retry, use the streaming host, pass
  `cached=true`, or register a webhook. A client that treats 2xx as terminal success will silently
  record an empty result.
- Rate limits: 600 req/min per API (excluding Streaming and Reveal). Read `x-ratelimit-limit`,
  `x-ratelimit-remaining` and `x-ratelimit-reset` (unix epoch seconds). No `Retry-After`. 401s
  consume budget.
- No `Sunset` or `Deprecation` headers. Retirements are announced only in prose on the changelog.
